# Papyr Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** App Android em Flutter que escaneia documentos com câmera própria, recorte manual e salvamento como imagens JPEG 100 ou PDF na memória pública, 100% offline.

**Architecture:** UI em Flutter com dois singletons `ChangeNotifier` (`library`, `session`) e um `ValueNotifier<int> tab`. Tudo que é Android (MediaStore, perspectiva em resolução total, PdfRenderer, compartilhar) fica num único `MainActivity.kt` atrás do canal `papyr/native`. Detector de folha e gerador de PDF em Dart puro.

**Tech Stack:** Flutter 3.44.5 / Dart 3.12.2 (local, `/snap/bin/flutter`), `camera` 0.12.1 (CameraX 0.7.5+1), Kotlin com APIs do Android SDK 36.

**Spec:** `docs/superpowers/specs/2026-10-17-papyr-scanner-design.md` (decisões). Snippets testados no emulador: `docs/superpowers/specs/2026-10-17-papyr-verification-notes.md` (citado abaixo como "notas L<linha>"). Em conflito, a spec vence.

## Global Constraints

- Flutter local `/snap/bin/flutter` 3.44.5. Não atualizar o Flutter nem o Gradle/AGP do template.
- `dependencies`: só `camera: ^0.12.1`. `dev_dependencies`: `flutter_test`, `flutter_lints` e `integration_test` (os três do SDK/template, fora do APK). Nenhum outro pacote. Kotlin usa só APIs do Android SDK.
- Package `com.pedroalves.papyr`, label `Papyr`, `minSdk = 30`, retrato, sem permissão `INTERNET` no manifest principal.
- Saída em JPEG qualidade 100 na resolução total. Nunca reduzir a imagem salva.
- Textos da UI em português, com a cópia exata dada nas tasks e na spec.
- Todo código Dart que usa o canal importa `import 'package:papyr/native.dart' as native;` e chama `native.<método>`.
- Erros do canal chegam como `PlatformException` com `code` ∈ {`memory`, `not_found`, `decode`, `io`}.
- **Limites desta máquina (ela já travou):** um build Gradle por vez; nada em paralelo com o emulador além do próprio teste; builds com `nice -n 15`.
- **Protocolo do emulador** (só nas tasks que pedem):
  - subir: `nice -n 15 ~/Android/Sdk/emulator/emulator -avd Medium_Phone_API_36.1 -cores 2 -memory 3072 -no-audio -no-snapshot-save >/dev/null 2>&1 &` e depois `adb wait-for-device shell 'while [ "$(getprop sys.boot_completed)" != 1 ]; do sleep 2; done'`;
  - conferir espaço: `adb shell df -h /data` (precisa de ≥ 1 GB livre);
  - o AVD é x86_64 com câmera traseira `virtualscene`;
  - interação manual: `adb shell input tap X Y`, `adb shell input keyevent KEYCODE_BACK`, screenshot com `adb exec-out screencap -p > /tmp/claude-1000/shot.png` e ver a imagem;
  - logs: `adb logcat -s flutter`;
  - desligar ao fim da task: `adb emu kill`.
- `/snap/bin/dart` não enxerga `/tmp`. Para scripts avulsos em `/tmp` use `~/snap/flutter/common/flutter/bin/cache/dart-sdk/bin/dart`.
- Commit ao fim de cada task, mensagem em inglês no formato `feat: ...` / `test: ...` / `chore: ...`.

## Review Focus

1. **Ciclo de vida da câmera sob troca rápida de aba, app em segundo plano e diálogo de permissão.** Esperado: o preview sempre volta, sem tela preta, e a lanterna real bate com o ícone. Coberto pelos passos manuais da Task 5 e da Task 6.

3. **Falha no meio do salvamento** (disco cheio, `OutOfMemoryError` numa foto enorme, CAP sumido). Esperado: "Tentar de novo" retoma sem duplicar; nenhum temporário fica no cache; erro de memória sugere remover a foto. Coberto por `test/save_test.dart` (Tasks 7 e 8).

5. **Voltar em cada etapa do salvamento** (durante o processamento, depois do sucesso, depois de Compartilhar) e voltar preditivo. Esperado: nada é salvo duas vezes e o editor nunca reabre com arquivos apagados. Coberto pelo passo manual da Task 7.

- [ ] **Step 3: Implementar o Kotlin**

Em `configureFlutterEngine`, a fiação das notas L268-279: `MethodChannel(messenger, "papyr/native", StandardMethodCodec.INSTANCE, messenger.makeBackgroundTaskQueue())`, com `try { result.success(handle(call)) } catch (e: Throwable) { result.error(errorCode(e), e.toString(), null) }`. Método desconhecido → `result.notImplemented()`.

`errorCode`, conforme a tabela da spec 5.3:
- `Fail` → o código dela;
- `OutOfMemoryError` → `memory`;
- `FileNotFoundException` e `SecurityException` → `not_found`;
- `ImageDecoder.DecodeException` → `decode`;
- outros → `io`.

Métodos (contrato na spec 5.3; corpos testados nas notas L301-326):
- `cacheDir` → `cacheDir.path`.
- `save` → notas L301-312, com `RELATIVE_PATH` `Pictures/Papyr` ou `Documents/Papyr` sem barra no insert. Antes do insert, `if (!File(path).exists()) throw FileNotFoundException(path)`. Depois de `IS_PENDING=0`, consultar a linha e devolver `{uri, name, size, date}`, com `date = DATE_ADDED*1000`.
- `list` → notas L313-315 (com barra no final no `relative_path IN (?, ?)`). Devolve `List<Map>`.
- `delete` → `contentResolver.delete(uri, null, null)`. Se devolver 0, `throw Fail("not_found", ...)`. `SecurityException` já vira `not_found`.
- `read` → `contentResolver.openInputStream(uri)?.use { it.readBytes() } ?: throw FileNotFoundException()`.
- `thumbnail` → por enquanto só imagem: `loadThumbnail(uri, Size(size, size), null)`, `compress(JPEG, 90)` e `recycle`. O ramo de PDF entra na Task 9.
- `share` → notas L320-326, executado com `runOnUiThread { startActivity(...) }`.
- `openAppSettings` → `Intent(Settings.ACTION_APPLICATION_DETAILS_SETTINGS, Uri.fromParts("package", packageName, null))` com `runOnUiThread`.
- `appVersion` → `packageManager.getPackageInfo(packageName, 0).versionName`.
- `cleanCache` → apaga do `cacheDir` os arquivos com `name.startsWith("CAP") && name.endsWith(".jpg")` ou `name.startsWith("papyr_")`.

Os argumentos `uri` chegam como String: usar `Uri.parse`. Números com `(x as Number).toInt()`.
